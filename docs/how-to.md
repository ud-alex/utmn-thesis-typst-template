
# Как использовать

## Ознакомьтесь с синтаксисом Typst

Здесь описаны только отдельные аспекты работы с Typst, которые специфичны для данного проекта. 

Прежде чем начать, ознакомьтесь с основами документации Typst на официальном сайте [https://typst.app/docs/](https://typst.app/docs/) или с иными туториалами.

## Структура проекта

Корневая директория шаблона содержит следующие ключевые элементы:

- `main.typ` – главный файл, в который подключаются все остальные части. Именно его нужно компилировать.
- `project_data.yml` – файл с персональными данными и параметрами нумерации (см. следующий раздел).
- `assets` - папка со вспомогательными файлами
  - `assets/gost_citation_styles.txt` - Этот файл содержит ссылки на примерные библиографические стили по ГОСТу, которые можно скачать и использовать в проекте. Файл носит информационный характер и не участвует в компиляции. 
  - `assets/appendix.typ` – вспомогательная функция для оформления приложений.
  - `assets/bibliography.bib` – файл с библиографическими записями в формате BibTeX (создаётся пользователем).
  - `assets/template.typ` – файл со стилями и общими настройками (поля, шрифты, нумерация). Редактируется только при необходимости глобальной смены оформления.
- `chapters/` – папка, содержащая все основные разделы работы:
  - `chapters/title_page.typ` – титульный лист (генерируется автоматически из YAML).
  - `chapters/intro.typ`, `chapters/first_chapter.typ`, `chapters/second_chapter.typ`, `chapters/conclusion.typ` – примеры стандартных глав с иллюстрациями функционала шаблона.
  - `chapters/bibliography.typ` – список литературы (требует активации, см. раздел о библиографии).
  - `chapters/appendices.typ` – приложения (используют функцию `#appendix` из `assets/appendix.typ`).
- `graphics/` – папка для изображений (PNG, JPG, SVG).

Все пути в `main.typ` уже настроены на подключение файлов из папки `chapters/`. При добавлении новых глав просто создайте файл в этой папке и добавьте строку `#include "chapters/новая_глава.typ"` в `main.typ` после остальных включений.

## Отредактируйте project_data.yml

Все ключевые метаданные вынесены в отдельный файл в корне проекта. Править исходный код вручную стоит только в исключительных случаях (некорректное отображение, необходимость кастомизации).

В этом файле заполните следующие поля:

- **Сведения об авторе**: `author`, `gender`, `year`, `university`, `city`, `institute`, `department`.
- **Данные о программе**: `major`, `major_code`, `submajor`, `education_mode`, `academic_year`, `education_level` (бакалавр / магистр / специалист).
- **Руководитель и завкафедрой**: `advisor`, `advisor_credentials`, `department_head`, `department_head_credentials`.
- **Дополнительные подписи** (рецензент, консультант): `thirdline_role`, `thirdline_credentials`, `thirdline_name`.
- **Настройки нумерации формул**:
  - `eq_numbering_style`: `"continuous"` (сквозная) или `"nested"` (по главам).
  - `eq_numbering_by_default`: `true` – нумеровать все центрированные формулы автоматически; `false` – только те, у которых есть метка (`<label>`).
- **Настройка нумерации теорем**:
  - `theorem_numbering_style`: `"continuous"` или целое число (см. раздел «Настройка нумерации»).

После изменения YAML-файла перекомпилируйте проект – изменения применятся автоматически.


## Что нужно знать (общие факты)

Отбивать начало новой страницы нужно вручную в начале файла с главой. 

По умолчанию секции первого уровня не нумеруются (ВВЕДЕНИЕ, ЗАКЛЮЧЕНИЕ). Для создания полноценной главы вида (ГЛАВА 1. ТЕОРЕТИЧЕСКАЯ ЧАСТЬ) используйте тэг <core_chapter>:
`= Теоретическая часть <core_chapter>`

Названия глав и подглав отображаются прописными (заглавными) буквами автоматически.

Если Вы используете сторонний пакет, то импортировать его нужно в каждый файл, где он применяется.

Для добавления приложений в конце работы используйте функцию `#appendix` из файла `/assets/appendix.typ`. Она сразу добавляет нумерацию в правом верхнем углу с заголовком посередине и индексирует его в «содержании».

## Библиографические ссылки

В шаблоне реализовано два способа формирования списка литературы.

### Ручное оформление (используется по умолчанию)

Этот режим не требует скачивания дополнительных CSL-файлов и даёт полный контроль над внешним видом каждой записи.

1. **Файл с записями** – `assets/bibliography.bib`.  
   Для каждого источника заполните поля `author`, `title`, `year`, `language` и **обязательное поле `note`**, в которое вы вручную вносите полное библиографическое описание в соответствии с ГОСТ.

   Пример записи:
```bibtex
@book{ivanov2020,
  author = {Иванов, И.И.},
  title = {Основы программирования},
  year = {2020},
  language = {russian},
  note = {Иванов И.И. Основы программирования : учебник / И.И. Иванов. – Москва : Наука, 2020. – 300 с. – ISBN 978-5-02-123456-7.}
}
```

2. **Стиль** – используется `assets/manual-entry-numeric.csl`.  
   Он сортирует записи: сначала русскоязычные, затем иностранные (по алфавиту), а в списке выводит только содержимое поля `note` с порядковым номером.

3. **Вставка ссылок в текст** – стандартная команда `@ключ` (например, `@ivanov2020`).  
   В месте ссылки появится номер в квадратных скобках `[1]`, а в конце работы автоматически сформируется список литературы.

Этот способ надёжен, не требует дополнительных настроек и гарантирует, что оформление будет именно таким, как вы напишете в `note`.

---

### Автоматическая генерация (экспериментально)

Если вы хотите, чтобы библиография формировалась автоматически из полей BibTeX (без ручного заполнения `note`):

1. Скачайте CSL-стиль по ссылке из файла `assets/gost_citation_styles.txt` (например, `gost-r-7-0-5-2008-numeric-alphabetical.csl`) и поместите его в папку `assets/`.

2. В файле `chapters/bibliography.typ` **раскомментируйте** строки с вызовом `bibliography`, указав путь к вашему `.bib`-файлу и скачанному стилю:
```typst
#bibliography(
  "/assets/bibliography.bib",
  title: "СПИСОК ИСТОЧНИКОВ",
  style: "/assets/gost-r-7-0-5-2008-numeric-alphabetical.csl",
)
```

   При этом **закомментируйте** или удалите строку с `manual-entry-numeric.csl`.

3\. Убедитесь, что в записях BibTeX заполнены все необходимые поля (author, title, journal, year, volume, pages и т.д.) – они будут использованы для генерации описания.

> **Важно:** готовые CSL-стили ГОСТ не всегда идеально соответствуют требованиям. При необходимости вы можете отредактировать CSL-файл вручную или вернуться к ручному режиму.

---

**Дополнительно:** в папке `assets/` вы найдёте файл `.bibliography.yml` – это пример записи в формате Hayagriva (собственный формат Typst). Он не используется по умолчанию, но может быть полезен, если вы решите перейти на этот формат.

## Настройка нумерации

В шаблоне предусмотрена гибкая настройка нумерации **только для формул и теорем (лемм, утверждений и т. п.)** через параметры в `project_data.yml`:

### Нумерация формул

**1. `eq_numbering_style` – стиль нумерации**
- `"continuous"` – сквозная нумерация по всей работе: `(1)`, `(2)`, ..., `(n)`.
- `"nested"` – нумерация внутри каждой главы: `(1.1)`, `(1.2)`, ..., `(2.1)`, `(2.2)`, ...

**2. `eq_numbering_by_default` – автоматическая нумерация**
- `true` – все центрированные формулы нумеруются автоматически.
- `false` – нумеруются только формулы с меткой `<label>`.

| `eq_numbering_style` | `eq_numbering_by_default` | Результат |
|-------------------|------------------------|-----------|
| `"nested"` | `true` | Все формулы нумеруются как (1.1), (1.2), ... |
| `"nested"` | `false` | Нумеруются только формулы с меткой `<...>`; номера вида (1.1), (1.2), ... |
| `"continuous"` | `true` | Все формулы нумеруются как (1), (2), (3), ... |
| `"continuous"` | `false` | Нумеруются только формулы с меткой; номера вида (1), (2), (3), ... |

**Ручное управление:**

```typst
// Явно задать номер
#math.equation(block: true, numbering: "(A.1)")[ $E = mc^2$ ]

// Отключить нумерацию
#math.equation(block: true, numbering: none)[ $1+1=2$ ]

// Включить нумерацию через метку (если numbering_by_default: false)
#math.equation(block: true)[ $a^2+b^2=c^2$ ] <pifagor>
```

Компилятор может иногда ругаться на ручное подавление нумерации. Добавление любого тэга `<label_name>` должно устранить ошибку.

### Нумерация теорем, лемм, определений и т. п. (из пакета theorion)

Управляется параметром `theorem_numbering_style` в `project_data.yml`.

| Значение | Результат | Пример |
|----------|-----------|--------|
| `"continuous"` | Сквозная нумерация | Теорема 1, Теорема 2, … |
| `1` или `"1"` | Нумерация внутри главы | 1.1, 1.2, 2.1, … |
| `2` или `"2"` | Нумерация внутри параграфа | 1.1.1, 1.1.2, … |
| `k` (целое) | Включает номера первых `k` уровней заголовков | При `k=2`: 1.1.1, … |

**Пример:**

```yaml
# Сквозная нумерация
theorem_numbering_style: "continuous"

# Нумерация по главам и параграфам
theorem_numbering_style: 2
```

Для отключения нумерации конкретного блока используйте `#theorem(numbering: none)[...].`

### Нумерация таблиц, рисунков и листингов

В отличие от формул, для этих элементов автоматическая настройка нумерации не предусмотрена, так как:

1. Они встречаются в дипломных работах реже.
2. В большинстве случаев достаточно сквозной нумерации по всей работе (Рисунок 1, Таблица 1, ...), которая реализована в шаблоне по умолчанию.
3. Настройка нумерации по главам для таблиц и рисунков потребовала бы усложнения кода, хотя и возможна при ручном редактировании template.typ.
